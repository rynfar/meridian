Baseline controls do not waive actual tools, model receipts, request decisions or cost bounds.

A separate parent static review found five issues in the first replacement. Each is corrected with focused discriminating controls:

1. Native SDK tools can be `mcp__oc__Agent` / `mcp__oc__Bash`. Only those exact supported names normalize for client receipt pairing. [Prefixed positive](prefixed-sdk-fixed.json) passes; wrong MCP namespace and wrong tool-name controls fail. IDs, names and canonical input ownership remain exact.

3. A client tool result must be on its own actor and on a request strictly after its originating tool terminal. Earliest receipts are preserved across history repeats. [Preissued correct-looking results](preissued-tool-result-rejected.json) fail.
4. The real proxy maps explicit Sonnet IDs to SDK tier `sonnet` with `ANTHROPIC_DEFAULT_SONNET_MODEL` as the exact version pin (`server.ts` model mapping / `explicitModelPin`, then `query.ts` env overlay). Exact wire model plus full SDK model or exact tier+pin and exact served-model receipts are required. Valid alias+pin passes; [missing pin](missing-model-pin-rejected.json), wrong pin, wrong wire ID and wrong served-model controls fail. This E72 false rejection was separate from E71's missing requested-model verification; no claim is made that the unchanged E71 harness rejected aliases.
5. Tool-bearing rows alone did not establish tool-less final/main-resume ownership. Exact complete SDK/HTTP final text is now held **only in memory** and combined with the private log resume witness. Every actor's full query count, exact resume/fork chain and disjoint SDK session identities must match its wire flow. [Equal-count swapped final SDK resume chains](swapped-final-chain-rejected.json) fail. Ambiguous final text or distinct IDs sharing a log prefix fail the owned benchmark, rather than establishing a general protocol identity guarantee.
