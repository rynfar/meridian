## Blocking diagnostic-design findings

1. **Unauthorized outer-bound change.** PLAN.md line 24 and the manifest propose 180 seconds of natural execution, then 5 seconds TERM grace and 10 seconds KILL/join grace. The parent's fixed outer process-group allowance is 70 seconds. Calling 180 seconds a diagnostic allowance does not resolve the conflict. Keep the parent's existing bound; do not change test/probe/turn deadlines. The plan is not approved as written.

2. **Wrong test selection.** The PLAN command supplies the idle test file without a test-name filter. That file contains six `it` cases; it would run all six, not the requested first case, “keeps a finished conversation for idleConversationMs, beyond the tool-result deadline.” PLAN's expected three factory observations and six HTTP responses confirm whole-file scope. The intended single case has one server and two HTTP sends on a successful path. Scope must be explicit; no run was authorized by this review.

3. **Detached-child cleanup is not established.** The unchanged runtime and probe both use `detached: process.platform !== "win32"` (`antigravityRuntime.ts:131`, `antigravityProbe.ts:39`). On macOS those fixture actors have separate groups. Killing only the Bun actor's process group cannot establish their termination. The preload observes child/pipe closure, but never signals or reaps external actors. `afterAll` can remain waiting on a stalled child, and it cannot perform cleanup once its actor has been killed. PLAN correctly warns about this, but supplies no validated parent custody record for the separate groups under the fixed 70-second bound. A `fixture-spawn-call` written before the actual spawn is not a PID/group witness; a kill in the spawn-to-return interval could leave that log without a returned PID. Missing ownership or joins must stay an explicit incomplete-custody outcome, not be treated as successful cleanup.

4. **Capture plumbing is designed, not validated.** PLAN's negative-control section is only a proposal. No offline self-check establishes that this Bun version intercepts named builtin imports and the backend export, that actual child/stream events traverse the patched `emit`, or that a non-200 clone body is captured without disrupting the original consumer. A green original test exercises no failed-response capture at all. Therefore the key new evidence path cannot be called proven. If this diagnostic is separately reconsidered, request a small separately authorized offline self-check/negative control for the exact observation plumbing: distinctive local 503 body; one underlying call; strict Promise/Response identities; original `bodyUsed` initially false and unchanged original readable body; original rejection identity; unmatched-call pass-through; known stdout/stderr lengths and close/join facts without forced stream flow. Do not inject a fake successful model/account or controls into the unchanged case. **The parent has chosen to stop; no helper implementation round is requested here.**

These findings were sent to the parent before any execution. The parent agreed to reject the current design and preserve the existing red gates.

## Secrets and false-green checks

- Exclusive artifact creation (`wx`, mode `0600`) prevents silently overwriting a previous run. A frozen hash-named read-only copy would be required before any separately authorized execution; none was made for this review.
- Fixed version/config/models argv and allowlisted conversation flag names avoid retaining prompt/model/workspace argument values. No raw environment, stdin or stdout/stderr chunks are logged by the observer.
- **The full failed HTTP body is deliberately unsanitized.** Backend error messages can include runtime error text and, for an exited conversation without a result, a stderr suffix (`antigravityRuntime.ts:187`). The fixture's fixed test input is synthetic, but that does not prove arbitrary inherited fixture settings or interpreter errors cannot enter the response. Keep the artifact private and inspect/redact it before any sharing; do not describe the full-body path as inherently secret-free. No actual leak was observed because nothing ran.
- `afterAllJoined` alone is not a coverage/success gate: `children.every(...)` is true for an empty list, and the cached boolean does not independently prove absence of later actors. Zero intercepted factories/spawns/HTTP calls can coexist with a green test exit. Require the expected selected-case witnesses, no observer/capture errors or uncounted chunks, final per-child joins, actor reap, and pipe EOF/close; missing evidence is incomplete instrumentation/custody, never absence of activity. This is an interpretation requirement, not a request to add production assertions.
