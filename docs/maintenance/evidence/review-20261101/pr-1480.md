## Why the opt-in became a rule

The PR added `MERIDIAN_KEEP_SESSION_ON_CLIENT_ABORT=1`. When a client stopped a streamed turn, Meridian kept the session instead of evicting it, so the next turn reused the prompt cache instead of replaying. That is safe only if the client discards the partial answer it showed.

| Client | After a stop |
| --- | --- |
| Pi 1.4.0, Prime Agent 0.9.5 | Discard the aborted message (read in their source; Pi also confirmed with the real client, model-free) |
| OpenCode 2.2.0 | Sends the partial back (real client, model-free) |
| Oh My Pi 16.3.2 | Keeps text and tool-call partials (read in its source) |

With the switch on, real OpenCode's next turn resumed a session that never saw the text the user had been shown: silent divergence, set by one operator-wide variable. The owner chose to make it correct for every client.

## The rule

- **On a stop.** When the client itself stops a streaming continuation after text reached it, and before any client tool call did, Meridian keeps the session. The durable record withholds its resume proof, using the existing empty-lineage-hash encoding every reader already answers with a replay. Restoring the proof needs an in-memory record bound to the exact store generation the marking wrote.
- **On the next request.** The session resumes only when:
  - the stored prefix is intact;
  - the session's own reply is unchanged;
  - what follows holds no assistant message of any kind and no `tool_result` for a call the session never made.

  Anything else replays fresh, with the partial.
- **Restarts and other processes.** Another process, a restart or any other store write costs one replay, never an unchecked resume.
- **Paths that keep main's behavior:** explicit cancels, a turn that already streamed a tool call, the watchdog, shutdown, non-stream turns, side requests and priority publications.
- **Where it lives:** the rule is the pure module `src/proxy/session/interruptedTurn.ts`. The session spec (*Interrupted turns*), ARCHITECTURE.md's Cancellation Contract and `docs/configuration.md` ("Stopping a turn", with the new `diverged=interrupted-turn-kept:<reason>` and `replay=` log fields) record it. The env var is removed.

## Review and corrections

Maintainer commits, all SSH-signed and verified:
- a merge of main;
- the fix, then a refactor into the pure module;
- docs and specs;
- the E79 gate;
- tests;
- round-4 docs, tests and a harness PATH fix.

**Two independent adversarial review rounds** found no sequence that resumes a session whose history differs from what the client shows. They covered:
- every partial shape;
- consecutive stops;
- edits and undo;
- restarts;
- other processes;
- concurrent reconnects;
- the headerless race.

Their lower-severity findings were all fixed: the logic moved out of `server.ts`, tests added for every reachable protection, the logs and specs corrected, and the harness isolated.

**Mutation run:** 38 of 39 protections fail tests when removed. The exception is stream completion awaiting a pending marking. It cannot be reached today, because `cancel()` aborts the request synchronously before the marking starts, so the catch always awaits it. It stays as a guard for the lease invariant.

## Follow-ups

Recorded in the handoff:
- **Stopped turns on the priority path** are not checked, as on main. A probe shows extending the rule fixes it.
- **An upstream failure after streamed output** leaves the session resumable, also on main.
- **A priority-routed abort** does not evict before its publication.
