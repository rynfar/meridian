## Review findings

1. **The described start-up exit does not happen with the bundled CLI.** Claude Code 2.1.296 (and 2.1.284) answers a logged-out `claude auth status` with exit 1. The pre-flight in `bin/cli.ts` uses promisified `execFile`, which rejects on a non-zero exit, so main prints "⚠ Could not verify Claude auth status" and keeps running. The "Not logged in" exit only happens with a CLI that reports `loggedIn: false` and exits 0; with a wrapper emulating that, main exits 1 and the head starts. On current CLIs the change still removes the misleading warning, the start-up spawn of the default context and its spawn on each auth-cache refresh.
2. **Older, not caused by this PR:** the pre-flight treats the CLI's exit-1 logout answer as "could not verify", so a no-profile, logged-out instance warns and starts instead of exiting. `models.ts` already handles this (#1323). Owner decision recorded in the handoff; a fix must land after this PR or profiles-only setups would start exiting.
3. **The `server.ts` keepalive wiring had no test.** Corrected (below).
4. **No spec recorded when the default context is checked.** Corrected (below).
5. A profile without overrides of its own is not kept warm by the 45 s keepalive on main or head (its status is cached under its own id, which the default-context refresh never served). Not a regression; recorded in the spec.
6. Checked with no defect: with profiles configured no route reads the default context (`resolveProfile` falls back to the first profile; `/v1/messages` including priority routing, `/health`, `/profiles/list`, `/v1/models`); `defaultProfile` naming a missing profile; keepalive targets recomputed every tick, so removing every profile at runtime restores the default refresh; ChatGPT seats and the Antigravity backend are unaffected; moving disk discovery earlier only sets a flag.
7. Follow-up, not this PR: `proxy-async-ops.test.ts`'s first test starts the background token refresh against the machine's default credential store, which on macOS reads the login Keychain during any local `npm test`. The added test uses file-backed stores.
